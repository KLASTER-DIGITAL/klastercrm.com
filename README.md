# KLASTER Site

Сайт `klastercrm.com` и личный кабинет. Next.js 15 (App Router), TypeScript strict,
Vercel. Требования и правила — в [CLAUDE.md](CLAUDE.md), содержание —
в [docs/01-спецификация-сайта.md](docs/01-спецификация-сайта.md).

```bash
npm install
npm run dev                                    # http://localhost:3005
npm run typecheck && npm run lint && npm run check   # перед коммитом
npm run build
```

## Что здесь

| Раздел | Где | Состояние |
|---|---|---|
| Главная, метод, компания, юридическое | `app/page.tsx`, `app/method`, `app/company`, `app/legal` | работает |
| Витрина линейки | `app/widgets`, реестр `lib/widgets.ts` | работает; в верхнее меню не выведена |
| Продукт «Аналитика» | `app/widgets/analytics/**` | работает: обзор, демо, тарифы, установка, документация, сравнение |
| Кабинет | `app/cabinet`, `app/login`, `lib/cabinet.ts` | вход по коду, плательщик, аккаунты CRM, лицензии, партнёрка; оплаты картой нет |
| Партнёрская программа | `/partners`, `lib/partner.ts` | 30–50% с платежей клиента, 10% за переданный контакт |
| Два языка | `lib/i18n*.ts`, переключатель `app/site/lang-switch.tsx` | русский основной, английский — зеркало, кука `klaster_lang` |
| Лицензии | `app/api/v1/license` | контракт для обоих виджетов; без `DATABASE_URL` никого не ограничивает |
| Заявки с лендинга | `app/api/v1/early-access` | работает |
| Фактура | `lib/company.ts`, `lib/pricing.ts`, `lib/funnel-data.ts` | единственное место хранения чисел |

## Чего ещё нет

Страницы продукта «Распределение KLASTER» — виджет написан, на сайте его нет, и в
`lib/widgets.ts` он не заведён. Раздела услуг, кейсов и блога. Живого кабинета:
входа, оплаты, истории платежей, статусов ключей. 

## Откуда взялся репозиторий

Сайт был частью репозитория аналитики и делил приложение с виджетом. Разделены,
потому что это разные сроки жизни: виджет стоит у клиента в amoCRM, сайт
переписывается каждую неделю, и релиз одного не должен трогать другое.
Виджет аналитики остался в `../../AMO Analitics` и отдаётся с
`klaster-analytics.vercel.app` — на него ведёт кнопка «Открыть демо»
(`lib/apps.ts`).

**Деплой.** Живой домен `klastercrm.com` обслуживает **хостинг Hostinger**, а не
Vercel: ответ несёт `server: hcdn` и `platform: hostinger`, A-записи ведут на
адреса Hostinger, заголовков Vercel нет вовсе. Hostinger собирает сайт из
GitHub-репозитория `KLASTER-DIGITAL/klastercrm.com`, ветка `main`, и опрашивает
его сам — вебхука нет. **Правки доезжают до людей пушем в `main`.**

`vercel --prod` из этой папки обновляет только площадку для проверки
`klastercrm-site.vercel.app`. Домена она не касается: `vercel domains inspect
klastercrm.com` отвечает, что домен настроен неправильно и ждёт
`A klastercrm.com 76.76.21.21`.

Свежесть живого сайта проверяйте по хешу чанка, а не по виду страницы:

```bash
curl -s https://klastercrm.com/partners | grep -o '/_next/static/chunks/app/partners/page-[a-z0-9]*\.js'
```

**У сборки на Hostinger нет переменных окружения.** Поэтому на живом сайте
кабинет отвечает `no_db`, а форма заявки возвращает `{"ok":true,"stored":false}`:
посетитель видит успех, заявка не сохраняется. Пока это не закрыто переводом DNS
на Vercel или заведением переменных в hPanel, живой сайт теряет обращения.

В репозитории аналитики копии файлов сайта теперь можно удалять — список в
`docs/02-разделение-репозиториев.md`.
