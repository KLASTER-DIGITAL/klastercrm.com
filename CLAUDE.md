# klastercrm.com — сайт и личный кабинет KLASTER

Витрина линейки виджетов для amoCRM и кабинет клиента. Отдельное приложение:
ни одного виджета здесь нет, и релиз сайта не может уронить продукт у клиента.

Источник истины по содержанию — `docs/01-спецификация-сайта.md`. Читать целиком
до правки страниц: разделы 0 (зафиксированные решения), 6 (навигация),
7 (дизайн-система), 8 (честность), 9 (план).

## 1. Три приложения, три репозитория

| Приложение | Репозиторий | Происхождение | Что отдаёт |
|---|---|---|---|
| Сайт и кабинет | этот | `klastercrm.com` | лендинг, страницы продуктов, кабинет, `/api/v1/{license,session,early-access}` |
| Аналитика KLASTER | `../../AMO Analitics` | `klaster-analytics.vercel.app` | `/widget` в iframe amoCRM и его API отчётов |
| Распределение KLASTER | `../KLASTER Distribution ` | `klaster-distribution.vercel.app` | интерфейс правил и приёмник вебхуков |

Виджеты ходят к сайту по HTTP за лицензией: `POST https://klastercrm.com/api/v1/license`
с полем `product`. Обратной зависимости нет и быть не должно — сайт в amoCRM не
ходит вовсе, это проверяет линт (`eslint.config.js`).

Адреса приложений живут в `lib/apps.ts` и больше нигде. Адрес аналитики оттуда
обязан совпадать с `APP_ORIGIN` в `widget/script.js` репозитория аналитики: скрипт
виджета сверяет с ним происхождение входящих `postMessage`. Разойдутся — сломается
приём сообщений внутри amoCRM, а не ссылка на сайте, и увидим мы это не здесь.

## 2. Правила, которые нельзя обойти

1. **Ни одного числа без источника.** Числа приходят из `lib/company.ts`,
   `lib/pricing.ts`, `lib/widgets.ts`, `lib/funnel-data.ts` — в разметке руками не
   пишется ни одного. Под числом на странице стоит сноска `<Source>`: аккаунт,
   период, метод.
2. **CTA не обещает больше, чем работает.** Нет выдачи ключа при установке — нет
   и «14 дней без карты». Нет платёжного провайдера — плашка раннего доступа
   остаётся. Список запрещённых формулировок — раздел 0 спецификации.
3. **Слабость называется первой строкой**, а не прячется в подвал (раздел 8).
   Отзывов нет, клиент один, в маркетплейсе на модерации — так и написано.
4. **Никаких выдуманных кейсов, отзывов и клиентов.** Единственный кейс —
   обезличенный пилот, и публиковать его можно только с письменным разрешением
   клиента (блокер №1 раздела 9 спецификации, не закрыт).
5. **Сгенерированная нейросетью графика — только абстракция:** фон, OG-картинка,
   иллюстрация к тексту. Никогда — интерфейс продукта, дашборды, люди, клиенты,
   офис, команда. Скриншоты продукта только настоящие, из демо-режима виджета
   (`public/shots/`).
6. **Новый продукт линейки заводится строкой в `lib/widgets.ts`**, а не вёрсткой.
   Витрина `/widgets`, подвал и перелинковка читают реестр и про конкретный
   продукт ничего не знают.
7. **Страница публикуется написанной целиком.** Половина страниц вполсилы хуже
   плотного одностраничника.

## 3. Проверки

Пакетный менеджер — **npm**. Не pnpm: хостинг читает поле `packageManager`,
лезет за pnpm через corepack и падает на `Cannot find module …/corepack/v1/pnpm/…`.
Для одного приложения без воркспейсов pnpm ничего не давал, а деплой ломал.

```bash
npm run typecheck && npm run lint && npm run check && npm run build
```

- `check:links` — ни одной ссылки в никуда. Отдельно ловит маршрут, который
  существует, но забыт в списке `PUBLIC` в `middleware.ts`: сборка и типы такую
  страницу пропускают, а посетитель получает 404.
- `check:facts` — контакты не разошлись: `lib/company.ts` и `lib/pricing.ts` с
  копиями в репозиториях виджетов, `widget/manifest.json` у соседей (адрес из
  карточки маркетплейса читает клиент, у которого виджет не открылся) и два
  литерала одного адреса внутри этого репозитория. Соседа нет на машине —
  проверка говорит об этом и не падает.

## 4. Доступ

Два уровня, весь разбор — в `middleware.ts`. Закрыто по умолчанию: новая страница,
забытая в списке `PUBLIC`, останется невидимой, а не станет дырой. `/cabinet`
целиком за кукой `klaster_session`; ссылка из шапки ведёт туда же и упирается
во вход — это честнее витрины с выдуманными данными.

## 5. Кабинет: что в нём есть и на чём он держится

Вход — по одноразовому коду на почту или телефон (`app/api/v1/auth/*`,
`lib/cabinet.ts`). Пароля нет и не будет. Код живёт 10 минут, сгорает после
пяти неверных попыток и после первого удачного ввода; в базе лежит хешем.
Витрины `/cabinet/demo` больше нет — она показывала выдуманную компанию
человеку, который пришёл за своей.

**Ключ лицензии — пара `(crm, external_id)`, а не `account_id`.** У amoCRM это
`account_id`, у Bitrix24 — `member_id`: адрес портала и поддомен меняются, эти
два идентификатора — нет. Один плательщик (`orgs`) держит сколько угодно
аккаунтов CRM (`crm_accounts`), счёт при этом один. Схема — `migrations/004_cabinet.sql`.

**Привязка аккаунта идёт изнутри аккаунта.** Вход по коду удостоверяет почту, а
не аккаунт CRM. Поэтому виджет, уже удостоверенный платформой, просит код у
`POST /api/v1/license/link`, человек вводит эти шесть знаков в кабинете. Ввод
номера аккаунта руками отдал бы чужую лицензию любому, кто видел адрес
поддомена.

**Письма уходят через ящик домена на Titan Mail.** `SMTP_HOST=smtp.titan.email`,
`SMTP_PORT=465`, `SMTP_USER=hello@klastercrm.com` — этот же адрес назван
контактным в `lib/company.ts` и `lib/pricing.ts`. `SMTP_PASS` в переменные
кладёт владелец: пароль ящика не проходит через код, репозиторий и переписку.
Без него `POST /api/v1/auth/code` отвечает `send_failed` и 503 — кабинет не
делает вид, что код ушёл.

**Чего в кабинете пока нет:** оплаты картой (провайдера нет, счёт выставляем на
юрлицо), приглашения второго человека, уведомлений. Каждое отсутствие названо
на экране словом, а не спрятано.

**Состояние `revoked` — не то же самое, что `canceled`.** Отзыв доступа
администратором CRM и неоплата требуют разных действий клиента, и общий ответ
«обратитесь в поддержку» стоит нам звонка.

## 5a. Партнёрская программа

Условия живут в `lib/partner.ts` и больше нигде: страница `/partners`, раздел
кабинета и расчёт начислений читают оттуда. Ставка, названная на витрине и не
совпавшая с начислением, — это спор с партнёром, который мы проиграем
независимо от того, кто прав.

Ступени 30% → 40% → 50% по числу активных клиентов, 10% за переданный контакт,
которого ведём мы. Обоснование ставок и разбор рынка — в шапке `lib/partner.ts`.
Клиент закрепляется за партнёром по первому касанию навсегда: метка `?p=<код>`
кладётся кукой в `middleware.ts` и не перетирается второй ссылкой.

## 6. Два языка: русский основной, английский — обязательное зеркало

Сайт целиком двуязычный, переключатель — в шапке (`app/site/lang-switch.tsx`),
язык живёт в куке `klaster_lang` (`lib/i18n.ts`, `lib/i18n-server.ts`,
`lib/i18n-client.tsx`). Правила:

1. **Каждая строка интерфейса — пара `{ ru, en }` рядом, в том же файле.**
   Отдельных файлов переводов нет. Серверная страница: `const t = tr(await getLang())`;
   клиентский компонент: `const { lang, t } = useLang()`.
2. **Меняешь русский текст — в том же коммите правишь английский.** Страница или
   компонент без английской версии не считается готовым.
3. Реестры (`lib/services.ts`, `lib/widgets.ts`, `lib/company.ts`, `lib/pricing.ts`)
   хранят текстовые поля как `Bi` — читать через `t(x)`, не через `x.ru`.
4. Числа: `fmt(lang)`, склонения: `count(lang, n, { ru: [...], en: [...] })`,
   перечисления CRM: `crmList(crm, lang)`, даты: `formatDate(iso, lang)`.
5. Проверка: `python3 scripts/checks/ru-audit.py` не должен находить русских строк
   вне пар `ru:` (id-якоря и словари этапов — допустимое исключение).

## 7. Дизайн-система и движение

Токены и кнопки — `app/globals.css` (первые 350 строк), оболочка сайта —
`app/site/site.module.css`, кабинет — `app/cabinet/cabinet.module.css`.
Onest — текст сайта, PT Sans — только внутри `.frame` (рамка amoCRM), JetBrains
Mono — сноски и ключи. Появление по скроллу и параллакс — `app/site/motion.tsx`:
`data-reveal` и `data-parallax` в разметке, `prefers-reduced-motion` отключает всё.

**Ни один текст не имеет права остаться невидимым.** Правило дороже эффекта:
прятать блок до срабатывания скрипта можно только с запасным выходом. Их четыре,
и трогать их нельзя по одному:

1. Эффект перезапускается на каждой навигации (`usePathname` в списке
   зависимостей). Без этого переход по меню оставлял новую страницу прозрачной
   навсегда: `Motion` живёт в корневой раскладке и повторно не монтируется.
2. Показанное состояние — атрибут `data-in`, а не класс. Класс, дописанный
   скриптом, React стирает при первой же перерисовке соседнего компонента.
3. Проверка на скролле не зависит от `IntersectionObserver`: что попало в окно,
   то показано, даже если наблюдатель промолчал.
4. Инлайновый скрипт в `app/layout.tsx` снимает `data-js` через четыре секунды,
   если `motion.tsx` не отметился. Не доехал бандл — страница просто видна.

Скрипт помечает блоки из списка AUTO **только на первом проходе** после
навигации. Пометить уже отрисованный блок — значит погасить текст, который
человек видит: появление обязано начинаться со скрытого состояния.

Параллакса нет ниже 720px (`PARALLAX_MIN_WIDTH`). На телефоне он сдвигал
карточки героя на полсотни пикселей вверх, и верхняя наезжала на кнопки.
